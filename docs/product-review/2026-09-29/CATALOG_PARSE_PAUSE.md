# SC-011 진행 · 가격표 자동 쓰기 중단과 수집 작업 권한

2026-09-29 · 상태: 일부 구현. PDF 파서 결과를 검증 정가로 자동 전환하지 않는다.

## 변경

- 기존 `catalog-parse`는 PDF 텍스트에서 가격과 트림명을 추정하고, 느슨한 이름 매칭으로 `trims.base_price`를 갱신하거나 새 트림을 만들었다. 검토 전 값이 출처 없는 기존 가격으로 다시 유입되는 경로여서 DB 쓰기 코드와 관련 보조 함수를 제거했다.
- 가격표 원문 다운로드·텍스트 파싱·로컬 JSON 미리보기는 유지한다. CLI와 루프에서 강제 실행해도 DB 쓰기는 일어나지 않는다. 기존 가격·원천 문서·트림 행은 운영 감사 전까지 보존한다.
- 로컬·운영 `catalog-parse` 스케줄 설정을 비활성화하는 마이그레이션을 추가했다. `ingest_loop_config` 수정과 `ingest_run_requests` 실행 요청 및 `ingest_runs` 열람은 관리자만 가능하도록 정책을 바꿨다. 일반 계정이 작업을 다시 활성화하거나 서비스 역할 작업을 큐에 넣을 수 없다.

## 검증과 남은 일

- 격리 DB에 정책 적용 후 `supabase/tests/catalog-parser-paused.sql` 통과: 스케줄 비활성화, 일반 계정의 설정·실행 요청·로그 접근 거부, 관리자 감사 접근을 확인했다.
- DB 자격 증명 없이 실행한 파서 미리보기 스모크 테스트, 워커 번들 빌드와 기존 Bun 테스트 통과. 운영 워커·스케줄과 과거 `base_price`의 출처는 확인하지 못했다.
- [정가 근거 검토](./MSRP_REVIEW.md)에서 원문을 트림별로 수동 대조하고 검증 가격을 별도 저장한다. 향후 자동 연동은 정확한 차량·트림 식별과 원문 위치, 검토 절차를 갖춘 뒤 새 경로로 구축해야 한다. 기존 파서 가격을 일괄 승격하지 않는다.
- `trims.base_price`와 `car_profiles` 과거 필드는 보존되어 직접 API에서 여전히 읽힐 수 있다. 소비자 가격 화면은 [검수 게이트](./PRICE_PROVENANCE.md)로 닫혀 있으며, 운영 데이터 감사·정정 전에는 이 수치를 공개 근거로 쓰면 안 된다.

운영에는 DB 마이그레이션과 워커 코드 배포가 모두 필요하다. `main` 병합만으로 적용 완료를 뜻하지 않는다.
