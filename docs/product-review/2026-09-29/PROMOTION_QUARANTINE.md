# SC-011 진행 · 검증 전 프로모션 격리

2026-09-29 · 상태: 일부 구현. 공개 가능한 공식 혜택 계약은 아직 없다.

## 변경

- `official_promotions`의 과거 행을 보존하되 익명·일반 계정의 직접 조회를 막았다. 관리자와 서비스 역할은 감사를 위해 계속 열람한다. 로컬 DB의 `promo-etl` 스케줄은 비활성화했다.
- 기존 자동 수집은 조건부 최대 혜택을 숫자로 파싱해 모든 트림의 할인액처럼 등록하고 `car_profiles.promo_*`에도 복사했다. 정확한 트림과 중복·적용 조건을 대조하지 않았으므로 이 DB 자동 쓰기 코드를 제거했다. 명령 실행과 강제 실행도 원문 JSON 미리보기만 만든다.
- `car-features`는 기존 `trims.base_price`, `car_profiles.promo_amount`, `official_promotions`를 가격·할인 근거로 쓰지 않는다. [검토된 정가 뷰](./MSRP_REVIEW.md)만 차량 기본 가격으로 읽으며, 공식 혜택 금액과 그에 따른 추정 백분위는 현재 `null`로 계산한다. 필수 DB 조회 오류는 빈 데이터로 처리하지 않고 실패로 올린다.
- 관리자 화면 명칭을 “프로모션 원자료”로 바꿔 현재 행을 검증된 공식 혜택으로 보이지 않게 했다.

## 확인 범위와 남은 일

- 격리 DB에 마이그레이션 적용 후 `supabase/tests/legacy-promotions-private.sql` 통과: 기존 행 보존, 일반 계정 비공개, 관리자 감사 접근, 스케줄 비활성화를 확인했다.
- 변경한 워커 모듈 Bun 번들 빌드와 앱 타입 검사 통과. 운영 워커 배포·스케줄 상태와 기존 행의 출처는 확인하지 못했다.
- `car_profiles.promo_*`의 과거 값은 보존되어 직접 API 조회가 가능하다. 소비자 화면은 [검수 게이트](./PRICE_PROVENANCE.md)로 닫혀 있지만, 운영 DB 감사·정정 전에는 공개 API의 이 필드를 신뢰하면 안 된다.
- 공식 혜택을 다시 열려면 각 혜택의 제조사 원문, 대상 트림, 필수 조건, 최대/확정 금액, 적용 기간, 중복 적용 가능성, 검토 시각을 별도 계약으로 구축해야 한다. 기존 원자료를 자동 승격하지 않는다.

운영 적용 순서는 DB 정책과 `current_trim_msrp` 마이그레이션, 이후 워커 배포다. `main` 병합은 운영 DB·워커 반영의 증거가 아니다.
