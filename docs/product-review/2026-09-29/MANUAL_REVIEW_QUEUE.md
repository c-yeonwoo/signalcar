# SC-016 선행 구현 · 견적 수동 검토 대기열

2026-09-29 · 상태: 부분 완료. 신규 견적 접수는 계속 닫혀 있다.

## 구현

- 견적 상태에 `reviewing`을 추가하고, 서버 지정 검토자(`quote_reviewers`)만 대기→검토 중→완료/실패로 전이할 수 있는 DB 함수를 만들었다. 검토자는 관리자 속성과 활성 검토자 지정을 **모두** 갖춰야 한다. 지정은 service role/DB 관리자 작업이며 앱에서 스스로 부여할 수 없다.
- 검토 중인 자기 담당 건에만 비공개 견적 이미지를 열 수 있는 Storage 정책을 추가했다. 완료/실패 후 검토자의 이미지 읽기 권한은 사라진다. 접수 이용자의 본인 열람·삭제 권한은 유지한다.
- 관리자 `/admin/quotes`에서 대기열 조회, 건 맡기, 이미지 열기, 서술형 결과 저장, 실패 이유 기록을 연결했다. 고객의 접수 ID로 새로고침 후 기록을 다시 찾을 수 있고 `reviewing` 상태가 보인다.
- 상태 변경은 행 잠금 아래 수행하며, 담당자가 아닌 사람·중복 완료·잘못된 입력은 거절한다. claim/complete/fail 사건은 `quote_review_events`에 남긴다. 이미지 다운로드 자체의 별도 읽기 감사는 아직 없다.

## 검증

- 격리 Supabase DB에 두 마이그레이션을 순서대로 적용한 뒤 `supabase/tests/quote-manual-review.sql` 통과: 일반 사용자·미지정 관리자 거절, 검토 전/후 이미지 접근 거부, 지정 검토자 맡기·완료·실패, 중복 완료 거부, 고객 결과 복구, 사건 기록. 테스트 트랜잭션 롤백.
- 타입 검사·대상 ESLint·프로덕션 빌드. 비로그인 `/admin/quotes` 직접 접근은 로그인으로 이동.

## 운영 개방 전 남은 것

1. 실제 검토 담당자를 정하고 서버에서 최소 인원만 지정한다. 운영 DB 마이그레이션/권한/Storage 정책을 실제 계정으로 검증한다. 현재 운영 접근이 없어 지정·배포를 하지 않았다.
2. 실제 이미지 파일 업로드→검토자 다운로드→완료/실패→고객 새로고침의 종단 간 테스트, 가림 누락과 이미지 판독 불가 처리 절차가 필요하다.
3. 검토 기준, 담당 시간·지연 알림·재배정/취소·수정 요청·이미지 열람 감사·보관/자동 파기·CS/환불 책임을 확정한다. 검토자가 휴직하면 현재 맡은 건을 재배정할 경로가 없다.
4. 기존 운영 Storage의 다른 허용 정책이 검토자 제한을 우회하지 않는지 감사한다. 동일 파일에 여러 진단 기록을 연결할 수 있는 레거시 경로도 정리해야 한다.

이 구현은 사람이 판단한 텍스트 결과만 저장한다. 자동 OCR·자동 가격 판정 또는 유료 납품을 약속하지 않는다. 운영 준비 전 신규 접수 화면은 열지 않는다.
