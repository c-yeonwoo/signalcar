# SC-011 선행 조치 · 가격 근거 미확인 자료의 공개 차단

2026-09-29 · 상태: 부분 완료. 가격 정보 타입·출처 계약의 최종 구현은 아니다.

## 조치

- `price_signals.evidence_kind`를 추가했다. 기존 모든 행은 `legacy_unverified` 기본값으로 남기고, 소비자 DB 읽기 정책은 `verified_contract`만 허용한다. 과거 행을 삭제하거나 실제 계약 자료로 재분류하지 않았다.
- 검증된 제보만 월·트림별로 집계하는 워커는 새 행에 `verified_contract`를 명시한다. 일별 특성 워커는 검증 신호만 조회하고, 해당 월 검증 제보가 없으면 과거 가격을 이번 달 표본으로 복사하지 않는다. 타이밍 사후 평가도 검증 신호만 조회한다.
- 소비자 코드에는 검증 여부를 `priceEvidence`로 전달하고, 검증 신호가 없을 때는 DB 중앙값·표본·BUY/WAIT 문구를 차량 모델에 복사하지 않는다.
- 그러나 현재 카탈로그의 정가, 프로모션, 옵션, 리뷰, 구매 시점 설명에도 별도 출처 검증이 없다. 모든 소비자 가격·추천·알림·계약 제보·견적 접수 경로는 우선 공통 **자료 검수 안내 화면**으로 닫았다. 차량명·트림·차체 종류만 검수 대상 목록으로 보인다. 관리자와 개인정보·약관 화면은 유지한다.
- 이 차단은 앱 화면 수준이다. 기존 인증 계정이 API를 직접 호출할 수 있는 권한은 별도 운영 정책 및 DB 감사 대상이다. 화면 차단을 서버 접수 차단으로 간주하지 않는다.
- 후속 [SC-015/018 선행 수정](./ACCOUNT_AND_RECORDS_GATE.md)에서 기존 견적 접수 기록의 열람·삭제 경로만 다시 열고 신규 업로드 UI는 계속 닫았다.

## 확인 범위

- 격리 Supabase DB에 마이그레이션 적용 후 `supabase/tests/price-signal-provenance.sql`: 과거 시드 행은 익명 계정에서 보이지 않고 검증 표시된 테스트 행만 보인다. 트랜잭션 롤백.
- 집계 워커 단위 테스트: 미검증·표시된 제보 제외, 출처 표시 확인.
- 타입 검사·빌드 및 로컬 브라우저에서 홈·탐색·비교·상세·코치·마이 경로의 공통 안내 화면 확인. 이는 운영 DB 적용/배포 검증이 아니다.

## 다시 열기 위한 조건

1. SC-010의 운영 DB·Storage·기존 열람권 감사와 필요한 백업/정정, 실제 적용 마이그레이션 확인.
2. SC-011/020/021: 정가·공식 혜택·검증 계약·추정·미확인을 값/출처/확인일/유효 기간으로 분리. 출처 없는 수치와 문구는 화면에서 숨기고, 표본 0이면 실거래 중앙값·분포·가격 변화·추천 판정을 표시하지 않는다.
3. SC-012: 계약 중복·취소·검수 상태를 반영하고 실제 관측 분포와 유효 표본을 재현. 최소 표본과 최신성 기준을 확정한다.
4. SC-014~017: 실제 계정 업로드·삭제, 보관/파기, 법적 고지·문의처, 운영 담당자·상태 전이, 결제/열람권 장부 확인 후 접수 경로를 연다.
5. 복구 전에 기존 화면의 예시 리뷰, 옵션 금액, 유지비, 프로모션, 미래 예측·보상 문구를 각각 제거하거나 출처 있는 값으로 교체한다. 현재 자료 검수 안내는 임시 안전 상태이며 상품 완성이 아니다.

운영에는 DB 마이그레이션을 먼저 적용하고 새 워커를 배포해야 한다. 현재 작업 환경에서는 운영 Supabase 접속이 되지 않아 두 작업의 운영 적용 상태를 확인하지 못했다. `main` 병합만으로 운영 DB와 워커가 갱신됐다고 간주하지 않는다.
