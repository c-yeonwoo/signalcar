# SC-010 운영 가격 자료 감사 준비

2026-09-29 기준 저장소 조사와 읽기 전용 질의 준비는 완료했다. **운영 데이터 감사·백업·정정은 아직 수행하지 않았다.** 현재 작업 환경의 Supabase 호스트 DNS 조회가 실패해 운영 행을 볼 수 없다. [읽기 전용 감사 SQL](/Users/ys.choi/dev-private/signalcar/supabase/audits/20260929_price_seed_audit.sql)은 개인정보 원본 없이 집계와 고정 시드 일치 여부를 확인하도록 작성했고, 격리 PostgreSQL 17의 최소 스키마/시드 예시에서 실행을 검증했다.

확인한 코드 경로:

- `20260714120000_gate0_trust_threshold.sql`은 고정 UUID 트림 10개와 2026-07 가격 중앙값·표본 수를 정적 숫자로 삽입하며, 충돌 시 7월 신호를 덮어쓴다. `20260715010000_real_catalog.sql`은 그랜저 1개와 앞선 3개 차종의 2026-02~06 히스토리, 프로필 문구·혜택을 삽입한다. 파일명 `real_catalog`는 실거래 검증의 증거가 아니다.
- `price_signals`에는 행별 원천 문서, 검증자, 시드 여부가 없다. `computed_at`이나 표본 수가 실제 계약의 증거는 아니다. `trims.base_price`와 `car_profiles.promo_amount`도 화면에 표시할 공식 원천/확인일을 저장하지 않는다.
- `aggregate-signals`와 `car-features`는 신규 조회를 검증 제보만 대상으로 수정했다([선행 수정](./VERIFIED_AGGREGATION.md)). 이 수정은 기존 `price_signals`와 공개 화면의 정정이 아니다.

운영 접근이 생기면 ① 대상 프로젝트와 마이그레이션 적용 이력 확인 ② 영향 테이블·원천 파일의 접근 제한 백업 ③ 읽기 전용 SQL과 실제 원천 대조 ④ 행별 `시드/검증 제보/공식 자료/원천 미확인` 분류 ⑤ 공개 중인 수치·문구의 정정 범위와 담당자 확인 ⑥ 격리 DB에서 정정·재집계 검증 ⑦ 운영 적용·복구 기록 순서로 진행한다. 검증 가능한 제보 원본을 새로 확보하지 않고 시드 행을 단순 삭제해 실제 값으로 간주하지 않는다. 사용자 계약 원본과 개인정보는 이 문서/깃에 넣지 않는다.

필요 입력은 운영 Supabase에 대한 권한 있는 **읽기 전용 접근 방법** 또는 감사 SQL의 결과, 운영 배포 URL/적용 마이그레이션 목록, 가격/혜택 원천 자료의 책임자다. 감사 결과와 분류가 확보되기 전 SC-010은 완료 처리하지 않는다.
